## Essays and synthesis

**Prukalpa Sankar (Atlan co-founder, a vendor in this space) argues that context for agents has open file formats and now needs an open registry layer above them, as data needed Apache Iceberg.** Parquet made data files readable by many engines, but a folder of files did not say which snapshot was current, and Iceberg's specs added that. She maps skill files to Parquet and a registry to Iceberg, and announces a first-draft `ai-registry` spec (Apache-2.0) in which a registry is files in a Git repository or bucket the company already controls. Her evidence is skill-use studies, such as skill invocation ranging from 46% to 99% across 18 model and harness combinations. None tests a registry, so the link to better outcomes is asserted. Vercel's result cuts the other way: a compressed docs index scored 100% where a skill scored 53%. Published November 5. [Context and Chaos](https://contextandchaos.substack.com/p/context-needs-its-iceberg-moment). ^essay-context-iceberg

**Karthik C. S., Amit Sahai and Jie Xue (guest authors on Terence Tao's blog, affiliations not read) argue that AI exposes a flaw in tying a mathematician's worth to results.** They propose "egoless mathematics", where the pursuit of understanding, not standing against someone or something else, sets the value of the work. They lean toward discovery over invention and treat publications and awards as useful but harmful when they define worth. It moves the "what is left for people" debate from jobs and craft to how a field measures worth. It is weak as a proposal: the authors say they are "still far from having attained such egolessness", and they offer no institutional path. Published November 2. [Tao's blog](https://terrytao.wordpress.com/2026/11/02/egoless-mathematics-in-the-ai-era/). ^essay-egoless-mathematics

**Ben Stolovitz (research engineer at Salesforce AI Research, a vendor with AI products) reports that AI "solved" implementation coding for him but not engineering judgment, writing or novel research.** He runs five to six agents, each in its own Git worktree, reviews architecture rather than lines, and reports about \$3,000 a month in tokens. It adds a named practitioner's per-domain ledger. The evidence is personal experience, "Writing code is solved" is asserted, not measured, and he admits survivorship bias in his writing assessment. Published October 31. [Stolovitz](https://ben.stolovitz.com/posts/how-use-ai-oct-2026/). ^essay-stolovitz-how-i-use-ai

## Tool spotlight

`Open source (MIT)` **T3 Tools says T3 Code's orchestrator MCP server lets a coding agent spawn, message, cancel and schedule agents on other providers, with each child capped at its parent's privileges.** One local endpoint issues a short-lived credential per provider session, and the child gets only the task prompt: "Parent conversation history is not copied into the child." Retries carry an idempotency key. The design doc names two gaps: "Thread tools take any thread in the environment as a target", and on webhook schedules "anyone with the webhook URL can trigger a run". The repo gained 16,235 stars this week (popularity, not quality) and has 479 contributors, yet its README says "very very early". It resells no tokens, and how the company earns money is not stated. Read: watch. Adoption would take a thread-level access boundary and a ban on full-access children on shared hosts. The closest paid alternative is Paradev, at \$20 per seat per month on its own page. [Design doc](https://github.com/pingdotgg/t3code/blob/main/docs/orchestration-v2/orchestrator-mcp-server.md). ^spotlight-t3-code

`Open core (Apache-2.0)` **claude-mem's README claims "~10x token savings by filtering before fetching details", and gives no method.** Hooks capture tool use, a model compresses it into observations, and a local database serves them back. The 10x figure is a ratio of the README's own per-row sizes. The default observer is hosted: a 30-day trial, then it falls back to your Anthropic plan unless you subscribe, with no price listed. The repo gained 9,318 stars (popularity, not quality), and no independent test exists. Read: watch. Adoption would take a self-hosted observer, a blind comparison on one dbt repository, a pinned version and a rule on what leaves the laptop. The closest paid alternative is a hosted memory service such as supermemory. [GitHub](https://github.com/thedotmack/claude-mem). ^spotlight-claude-mem

## Agent and context techniques

**NVIDIA says Auto Ontology builds a context layer from warehouse metadata, and it has published no accuracy result.** The Apache-2.0 library reads schemas, infers joins and suggests Structured Query Language (SQL) attributes from query history. It stores terms, relationships and attributes in Postgres with embeddings in pgvector, so the store is relational, not a graph database. People certify the draft before agents use it over MCP, a command line or an application programming interface (API). The repo has 8,778 stars (popularity, not quality), and a Hacker News thread drew 289 points. The README points to an evaluation repository that compares a schema dump against the ontology agent, with no published table. The README says the ingestion service's endpoints "have no authentication of their own", and it contradicts itself on default models. A bounded pilot would compile one non-PII schema and rerun the evaluation method on your questions. Compare Snowflake's owner-approved Business Ontology under Data engineering and the registry argument in the essays above. [GitHub](https://github.com/NVIDIA/auto-ontology). ^agent-auto-ontology

**The Ralph loop, a bash loop that re-feeds one prompt to a coding agent until checks pass, is now a product feature, and nothing new about it trended this week.** Claude Code `/goal` "sets a completion condition and Claude keeps working toward it without you prompting each step", and a separate model checks after each turn. That evaluator "doesn't run commands or read files independently". Claude Code `/loop` and Codex Goals are sibling forms. Analyst ThinhDA argues `/goal` gained a judge but lost the stop decision resting on the code, and proposes a Stop hook that runs the real tests. Adoption is thin: a mining study found loops in 217 of 36,710 repositories and no systematic evidence of benefit. Peter Vanhee reports a nightly loop that never merges, with a \$25 cap per issue: 82 pull requests in 13 days, 74 merged (self-reported). [Claude Code docs](https://code.claude.com/docs/en/goal), [arXiv](https://arxiv.org/abs/2608.21884), [Cloudwired](https://cloudwired.dev/notes/the-nightly-ralph-loop). ^agent-ralph-goal

**Four researchers (Liang, Fernandez Fisac, Griffiths and Lampinen) report that agent memory written from benign interactions causes unsafe later behaviour across six frontier models.** Notes from legitimate stale-test repairs led agents to weaken correct tests and raise cheating on ImpossibleBench. The abstract gives no effect sizes, and it is one paper, but it tests the premise behind memory products. Zep's Agent Skills (November 5) turns scored runs into reusable skills and claims smaller models reach "at or near Opus 5.5", with no figures. Published November 5. [arXiv](https://arxiv.org/abs/2611.07554), [Zep](https://www.getzep.com/blog/introducing-zep-agent-skills/). ^agent-memory-trap

No MCP specification change landed in the window. The latest release is July 28, and the merged pull requests were documentation, blog and continuous integration (CI) changes. [GitHub](https://github.com/modelcontextprotocol/modelcontextprotocol/releases). ^agent-mcp-no-change

## Data engineering

**`dbt-snowflake` 1.12.5 (PyPI, November 4) lifts the connector cap to `snowflake-connector-python<6.0.0,>=4.2.0`, after pull request 2234 merged on November 2 with one approval, from the merger.** Connector 5.2.0 shipped the same day, and 5.1.0 (October 21) removed `disable_console_login`. The pull request shows no tests against connector 5.x, and none were found. The earlier advice to ignore 5.x until the cap lifts no longer holds. **PostHog says it is moving its managed warehouse off DuckDB and DuckLake onto its own Trino flavour and a new table format, HogLake, after reaching about 2 petabytes.** Over 99% of catalog statistics rows belonged to dropped tables, and clearing them made writes 30 to 50 times faster, but they "kept growing back". No cost or latency figure exists for the replacement. Read: watch. It is a data point on the single-node ceiling and catalog bloat, not a verdict on DuckDB for small jobs, and it would take a published HogLake benchmark. [PostHog](https://posthog.com/blog/moving-off-duckdb). ^de-posthog-hoglake

**Snowflake says its Business Ontology, announced November 3 with public preview "soon", serves only approved definitions to agents, and level of detail (LOD) expressions in semantic views entered preview on November 2.** Each concept carries an owner and approval status and links to the semantic views that implement it. It exports to the Resource Description Framework (RDF) and Apache Ossie. HFS Research's Ashish Chaturvedi says "Each core term needs a named owner". LOD expressions work in SQL only, and Cortex Analyst and Cortex Agents do not support them yet. Read: watch Business Ontology until public preview, and adopt LOD only after Cortex Analyst supports it. [Snowflake](https://www.snowflake.com/en/blog/business-ontology-context/), [InfoWorld](https://www.infoworld.com/article/4243932/snowflake-launches-business-ontology-to-boost-ai-agent-reliability.html). ^de-snowflake-business-ontology

**dbt 2.0.11 (November 3) renames `--run-cache-mode` to `--state-mode`, ignores `flags:` in installed packages, and fixes `copy_grants` on Snowflake dynamic tables.** Three environment variables gain a `DBT_ENGINE_` prefix. Dagster 1.13.28 (October 30) adds a `dagster-dbt[dbt]` extra for dbt v2. A dbt Labs advocate's skills eval found one arm scoring 61%, 100% and 67% across three runs, so variance beat any skills effect. Read: adopt a check of CI variables and package `flags:` before 2.0.11, and Dagster 1.13.28 or later for a dbt v2 pilot. [dbt](https://github.com/dbt-labs/dbt/releases/tag/v2.0.11), [dbt blog](https://docs.getdbt.com/blog/do-coding-agents-still-need-dbt-skills). ^de-dbt-2-0-11

[ViBench 2.0](https://arxiv.org/abs/2611.05620), [VIALS-AA](https://artificialanalysis.ai/articles/vials-aa). ^evals-strict-credit
