## Evals and measurement

**"Whose Facts Count?" audits two of the field's most-cited eval instruments and finds a structural bias, not an incidental one.** Chatbot Arena's conversations run 76.3% English against an estimated 25.9% English share of the global internet population. A single rater's focus on Colombian history alone inflated Global South representation in one subset by 2.70 percentage points. The paper's own 50-item cultural-responsiveness counter-benchmark scored roughly 3x better on cultural-responsiveness metrics than OpenAI's SimpleQA (Cohen's d = 1.01), which the authors frame as "structural validity failures, not incidental measurement problems." What it changes: a leaderboard rank built on SimpleQA or Chatbot Arena is a rank on English-speaking, US/Europe-weighted knowledge, not general knowledge, and that gap is now measured rather than assumed. [source](https://arxiv.org/abs/2609.24934v1)

**OSWorld-Pro shows how much of a computer-use score comes from grading only the ending.** It scores 2,800+ subgoals across 300+ tasks against 67,000+ human annotations instead of a single pass/fail outcome. Claude Opus 5 drops from 83.4% on the original outcome-only OSWorld to 75.7% under process scoring, a 7.7-point gap on the same model from the same tasks. Failure analysis surfaces "subgoal-irrelevant actions and click-based mistakes" as their own error class, invisible to an outcome-only grade. What it changes: any OSWorld number quoted without saying which OSWorld now needs a caveat, since the two scores measure different things on the same run. [source](https://arxiv.org/abs/2609.24890v1)

**GameLogicBench finds real headroom in a capability axis no one was measuring: whether an agent's code obeys game rules while the game is actually running.** 72 tasks, 403 hand-designed scenarios, 1,451 test cases via seeded variation, 20 model/scaffold combinations. Best model success rate: 52.78%, falling further as task complexity rises. The authors needed mutant implementations to validate their own harness, because without them "incorrect agent submissions passed." Agents also showed a tendency to copy code from public repositories when network access was available, which the paper treats as an evaluation-environment requirement rather than a capability finding, but it is a reminder for anyone building agent evals with live network access. [source](https://arxiv.org/abs/2609.21562v2)

**CCTU's AACL acceptance revision puts a sharp number on compound tool-use constraints.** 12 constraint categories across 4 dimensions, 200 cases averaging 7 constraints each. No model exceeds 20% task completion under strict constraint adherence, and models violate constraints in over half of cases, with "limited capacity for self-refinement even after receiving detailed feedback on constraint violations." A single-tool-call benchmark and a realistic multi-constraint tool-use benchmark are not measuring the same skill. [source](https://arxiv.org/abs/2603.15309v2)

**DolphinBench is a framework paper, not a leaderboard yet, but its design principle is worth adopting on its own.** It targets agent memory specifically, scoring a Pareto frontier of accuracy, cost, and latency together rather than accuracy alone, across 600 tasks built from three knowledge-work personas with roughly 500,000 tokens of history each. Its task-validity rule, running an agent with and without the relevant history and requiring success with it and failure without it, is a reusable technique for anyone building a memory eval in-house, independent of whether DolphinBench itself gets adopted. [source](https://arxiv.org/abs/2609.24971v1)

## Agent and context techniques

**Claude Code's AGENTS.md support silently does nothing for a specific, common population: telemetry off, or running through Bedrock, Vertex, or a gateway.** AGENTS.md loading ships as a built-in plugin, off by default, gated behind a remote feature flag (`tengu_agents_md_mod`) fetched over the same channel as telemetry. Set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` or `DISABLE_TELEMETRY=1`, or run through Bedrock, Vertex, or Foundry, and the flag fetch never happens, so a purely local markdown file read is silently blocked with no error and no warning. An Anthropic engineer confirmed on Hacker News this is a rollout artifact, not a design choice: "we needed a way to turn this off remotely via feature flags if it broke something, and with telemetry off you don't get those." A documented one-line workaround exists: put `@AGENTS.md` in a local `CLAUDE.md` to import it directly. Action item, not a wait-and-see: confirm AGENTS.md is actually loading in any Claude Code deployment running with telemetry disabled or through Bedrock/Vertex/Foundry, since exactly that population is the one most likely to rely on a shared instruction file. [source](https://github.com/anthropics/claude-code/issues/95690)

**google/ax is a Kubernetes-style declarative orchestrator built specifically for agent workloads, with cost and isolation controls as first-class primitives rather than bolted-on limits.** Four YAML manifest types: Task (sandboxed execution with resource limits), Workspace (pre-warmed repos, MCP servers, skill packages), Gateway (outbound-traffic allowlisting), Model (provider/credential management), driven by a kubectl-style CLI with multi-cluster support. The stated reason existing orchestration tooling doesn't fit: agent workloads "accumulate state, need strict isolation, call out to model APIs and tool servers, and can burn money in a loop if nobody is watching." Pre-stable, 8,000+ GitHub stars, maintainers say the API will likely break before a stable release. [source](https://github.com/google/ax)

**fast-jev-compaction replaces Claude Code's default context-compaction summarization with decision-model-scored, selective tool-call pruning.** Instead of summarizing old turns, it keeps all text verbatim and sends only tool calls and results to TypeSafe AI's Jev, which scores each one on whether it's worth keeping and whether its result needs to stay verbatim; anything below threshold gets truncated to roughly 300 characters or dropped entirely. No published benchmark yet comparing token savings or task-success retention against default compaction, so this is an architecture claim, not a measured one. It's a concrete extension of two threads already on the radar: the coordinator/external-task-board pattern from yesterday, and the Jev/decision-model class tracked since mid-September, now with a real consumer use case rather than just a benchmarking target. [source](https://github.com/tamaratran/fast-jev-compaction)

## Security

**ShinyHunters claims a breach of FBIjobs.gov, the FBI's applicant and employee job portal, alleging access to sensitive data on agents and job applicants.** The FBI has confirmed only that it is aware of the claims and is investigating; the scope of the claim is unverified beyond the attacker's own statement. [source](https://abcnews.com/US/wireStory/fbi-investigates-apparent-breach-jobs-website-hackers-claim-136686678)

**A supply-chain attack compromised AI agent-memory vendor MemTensor's own release pipeline, not a downstream package.** Attackers obtained a publish token during a CI release job and used it to push malicious versions of MemTensor's `memos-cloud-openclaw-plugin` on npm and its `MemoryOS` package on PyPI, both carrying the same credential-stealing malware, built to target developer and CI secrets including cloud and source-control tokens, and reported to also capture prompt text sent to AI agents on infected machines. The reporting also describes worm-style self-propagation templates aimed at other npm packages, Python packages, and GitHub Actions workflows. Why it matters: this targets exactly the credentials and pipelines that AI/agent development teams rely on, and stealing the token during the release job itself (rather than compromising an already-published artifact) sidesteps the usual "rotate the package" response, since the token was the thing taken. Treat this as a prompt to review CI release-pipeline token scoping and rotation, not just dependency pinning. [source](https://thehackernews.com/2026/09/compromised-memtensor-packages-deliver.html)

## Society and economics

**Inference cost is falling roughly 47% per quarter, and that trend line matters more than any single open-weight release.** Marginal Revolution's Alex Tabarrok, citing Epoch AI's cost analysis, reports that the price of hitting a fixed capability level (75% on GPQA Diamond) fell from about \$0.30 per question with OpenAI's o3 in January 2025 to about \$0.0004 with GPT-5.6 Luna in mid-2026, a roughly 725-fold drop in under 18 months, "an average of some 47% per quarter" sustained over three years. The framing worth carrying: falling inference cost cuts both ways on the "open-weight versus frontier" argument, since frontier labs get cheaper at any fixed capability level too. [source](https://marginalrevolution.com/marginalrevolution/2026/09/the-price-of-intelligence-is-falling.html)

**Acer's CEO publicly disputed the memory-shortage narrative behind rising PC prices, tying it to AI-driven demand and supplier margin protection rather than a genuine multi-year scarcity.** Jason Chen: "It's impossible for the shortage to last until 2030," arguing suppliers "keep putting out the message... to protect margins amid AI-driven demand." He projects PC prices rising 5 to 20% through Q4 2026 before declining from mid-2027 as Chinese memory capacity comes online. Treat this as one contested industry viewpoint, not a settled figure; major memory makers maintain shortage projections well past 2027, and Acer, as a price-taker on DRAM costs, has its own incentive to say the shortage is overstated. [source](https://www.tomshardware.com/pc-components/dram/acer-ceo-says-memory-makers-are-hyping-2030-shortage-fears-to-protect-margins-pc-prices-set-to-decline-by-late-2027-cheaper-chinese-capacity-coming-online-delivers-lower-memory-prices)

## Practitioner layer

**Three independent practitioner posts landed on the Jev/decision-model class the same day, which is itself the signal.** One is a technical critique arguing Jev's confidence scores aren't properly calibrated, citing an example where it predicted a fair coin landing heads at 0.92 probability even with the correct answer stated in the prompt, and recommending teams treat its output as a ranking score and apply their own lightweight recalibration rather than trust the raw probability. A second is a deliberately labeled parody, a 25-line local reproduction using an open GGUF model's own logits instead of an API call, "no RLCD training step," which the author frames as showing how much of the hosted product's mystique is unnecessary for the core mechanic. A third, thinner post covers using Jev-style typed decisions with scoped tool authority in production. Read together: a hyped decision-model category is now being reproduced and picked apart by practitioners faster than the vendor is responding to either. [calibration critique](https://alexmolas.com/2026/09/23/jev-cant-be-calibrated.html) · [parody reproduction](https://www.nobodywho.ai/posts/jev-in-25-lines/)
